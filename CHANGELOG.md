## 0.2.0

11 October 2026. Hardening: a background is rebuilt from a table of what each kind of dictionary keeps, `sanitize` bounds what a file decodes to and how long it may take, and qpdf runs in a worker of its own for each file.

- A background passes `qpdf --check` with no warning: its trailer's `/Size` is one more than its highest object number. SF 182's said 1,739 where the highest was 1,679, and the backgrounds of the three dynamic forms and of the sample were off the same way.
- A background carries no `/ID`. `sanitize` run twice on one file, two seconds apart, returns the same `form.pdf` byte for byte: qpdf wrote a fresh second element of the `/ID` on each run, and six published forms and the sample carried it.
- `quillify` writes each string it puts in `Quill.yaml` and `example.md` as a JSON string literal, with a lone surrogate made U+FFFD and U+007F to U+009F, U+FFFE and U+FFFF written as `\u` escapes. A tooltip, an option or an example that holds one of them builds into a quill, the engine reads the character back, and the example renders. A lone surrogate in a tooltip is made U+FFFD in `form.json` too.
- `sanitize(pdf)` rejects with a `TypeError` for anything that is not a `Uint8Array`, before it starts a worker. A `DataView` or a wider typed array used to get past that check, and a `DataView` left a pdf.js worker running. An `Int8Array` and a `Uint8ClampedArray`, which were read as bytes, now throw too. A `Uint8Array` made in another window is still read.
- A background keeps a form's layers (`/OCProperties`) and their default state as the file has them, and so does the rendered form. Content in a layer that is off on screen or in print stays in the background, and a reader that ignores optional content shows it.
- A dynamic form whose one page area may occur once in its page set converts where it ended `sanitize` with pdf.js's `Cannot read properties of undefined (reading 'length')`: AF 715, AF 716 and DAF 357 do, to two pages each. The pdf.js worker the package ships is changed at a third line for it.
- A dynamic form with an overflow leader before a row that cannot fit no longer keeps pdf.js laying out pages for good. `sanitize` settles on DAF 1024, and with the other changes of this release the form converts, to five pages and 198 fields. The pdf.js worker the package ships is changed at two more lines for it.
- A dynamic form converts when a field is named as the subform beside it, has no name, or has a name that ends in a period. Each ended `sanitize` with pdf-lib's error, on twelve of the Air Force's published forms.
- A dynamic form over 20 pages is refused as `too_many_pages` before a page of it is laid out in the host page. It was laid out in full first. A form over the cap that holds an image or a dashed border is refused for its pages, where it was `unpaintable`.
- A dropdown with `;`, `>` or `|` in an option builds into a quill. The engine refuses those characters in an enum value, so `quillify` returned its problem for DAF 64 and AFMC 21 and no naming kept the field. Such a dropdown is now a string field with the first option as its example: the quill has a text box where the published form has a dropdown, and lists none of the options. A dropdown without those characters is unchanged.
- `suggest` names two options of one group that share a tooltip from the tooltip and each option's on-state, and describes each with its on-state in parentheses after the tooltip. WH-380-E's `job_description` and `job_description_2` are `job_description_is` and `job_description_is_not_attached`.
- A background's page is the frame its fields were measured in. `sanitize` writes each page's MediaBox from pdf.js's view of the page, where it wrote the `/CropBox` as pdf-lib read it: a crop box that reaches past its media box moved every field off its box, and one that is a number or has three entries ended `sanitize` with pdf-lib's error. A file whose pages pdf.js and pdf-lib read as different objects, or as more or fewer, is refused as `damaged`: one with a page that names its `/Type` by reference, whose background came back a page short, and one whose page tree has a `/Count` lower than its pages, which came back as a form. No page of the 49 measured forms that convert changes size.
- `sanitize` rejects when the host page takes the frame a form is laid out in out of the document, or into another one, before the frame has loaded, with an error that says so and with no worker started. It used to stay pending for good.
- A `zoom` on the host page no longer moves what `sanitize` reads off a dynamic form. The frame the form is laid out in undoes the zoom, and under `html { zoom: 1.5 }` DD 2875 reads as it does on a page with no zoom, where its text sat up to 1.02 pt off. Where the zoom cannot be undone exactly, `sanitize` rejects with an error that names the host page's zoom: a `zoom` marked `!important` on the frame, and some values, 1.7 among them.
- `sanitize` answers for a field tree pdf-lib's form API cannot type, where it threw pdf-lib's error: a field whose `/FT` is a string or a number or sits on its widget alone, an entry of `/Fields` that is no dictionary, an `/AcroForm` that is a number, and a field that is its own kid. A tooltip of any length comes back whole, where one of 130,000 characters ended the call with a `RangeError`. A field tree of any depth is read too, where one 5,000 deep ended it the same way, and a deep one takes pdf.js time: 18 s at 10,000 deep, and `sanitize` still has no deadline. Reading a hybrid form no longer writes pdf-lib's "Removing XFA form data" warning to the host's console. The fields and tooltips of the 59 measured forms are what they were.
- A dynamic form pdf.js cannot lay out is refused as `layout`, a new refusal code, with pdf.js's reason as its `detail`. Every such failure used to end `sanitize` with pdf.js's `Cannot read properties of undefined (reading 'length')`, whatever went wrong. No form of the 59 is refused this way. The pdf.js worker the package ships is changed at a sixth line for it.
- A file with an array or a dictionary of more than about 125,000 entries on a page no longer ends `sanitize` with a `RangeError`. A file of under 2 kB could hold such an array. Writing `Quill.yaml` for a choice with as many options no longer overflows the stack either.
- A static form's background keeps each page's content streams as the file has them, where qpdf used to join them into one, so a `form.pdf` differs in bytes from the one 0.1.0 wrote and is up to 3,187 bytes larger on the fixtures. A page whose content decodes to 1 GiB no longer runs qpdf out of memory. The file qpdf writes holds no object stream, so pdf-lib no longer reads a stale one over the file's own objects, which ended `sanitize` with an error on AF 1520.
- A dynamic form with a page pdf.js gives no size is refused as `layout`, with `a page has no size` as its `detail`: a width or a height that is no number, zero or negative. The first ended `sanitize` with pdf-lib's `TypeError`, and the others came back as forms on a page of the wrong size.
- `sanitize` runs qpdf in a worker of its own for each file and ends it with the call, so a page no longer stops converting after about 386 files, a file that crashes qpdf no longer breaks the files after it, and the page's thread is free while qpdf runs. The package ships a fourth asset for it, `assets/qpdf.worker.js`, a classic worker that a bundler has to copy and a host page has to allow, and it fetches `qpdf.wasm` itself, once for each file. A file costs about 20 to 30 ms more. A missing `qpdf.worker.js` rejects with an error that names it, as a missing `qpdf.wasm` does. A file that sends qpdf into a loop used to stop the page and now leaves its one call pending with a worker busy: `sanitize` still has no deadline.
- A file that qpdf gives up on partway is refused as `damaged`. `sanitize` used to go on with the part qpdf had written, a file cut short: a page whose second content stream is LZW that cannot be decoded was refused as `not_pdf`.
- The package no longer depends on `@neslinesli93/qpdf-wasm`. It ships the two files it takes from it, so a consumer installs `pdfjs-dist` and `pdf-lib` and brings the engine as a peer.
- A file that comes to more than 64 MiB with its streams decoded is refused as `too_large`, with 67,108,864 as its `limit`, where the 8 MiB cap bounded only the file as stored: a page of about 1 MB whose content inflates to 1 GiB used to come back as a form, and so did a file of 4.2 MB whose 100 images lie inside one another, with a `form.pdf` of 420 MB. So is a file that has qpdf write or hold more than 64 MiB. `limit` tells the two bounds apart. `sanitize` now uses the browser's `DecompressionStream`.
- A file with a stream that cannot be counted is refused as `damaged`, where it used to convert: a Flate stream zlib rejects, a stream under RunLength, under a filter the library does not know or under more than one filter before an image codec, and a stream that is typed as an object stream or a cross-reference stream and is neither. That last one is found by its name, so any name that is `/ObjStm` or `/XRef` or begins with one gets its file refused, wherever qpdf wrote it. None of 1,423 published files is refused for any of these.
- A static form's `form.pdf` differs in bytes from the one before: qpdf now writes every stream it can decode back as one Flate stream. On the fixtures it is 1 to 4,633 bytes smaller.
- A background's page resources, images, forms and stream dictionaries keep a listed set of keys each, as its catalog, pages and links did. An application's private data on a form (`/PieceInfo`, with the date beside it) no longer rides into a quill, nor does a stream's reference to a file outside (`/F`), a key nobody listed on a `/Resources`, or a stream or a dictionary under `/XObject` that is neither an image nor a form. A key of a page or a link that is read as a number, a name or a string (`/Rotate`, `/Rect`) no longer carries a dictionary there, and a page's `/Parent` stays only when it names the page tree. `sanitize` refuses as `damaged` a file that names one of its pages as something else too, a page tree's `/Resources` say: an object in a background is of one kind, and that page would be no page. No page paints differently: of 857 published forms, 12 backgrounds change, each of them smaller.
- A background's fonts, graphics states, color spaces, functions, shadings, patterns and transparency groups keep a listed set of keys each, and so does what each leads to: a font descriptor, an encoding, a CMap, a font file, a soft mask, an ICC profile. A key nobody listed on one of them no longer rides into a quill with the object under it, and a dictionary or a stream of no known sort is taken out of a page's `/Font`, `/ColorSpace`, `/Shading` or `/Pattern`. A color space array that holds a dictionary or a stream ends at the last part its family has. No page paints differently: of 857 published forms, 22 more backgrounds change, each of them smaller.
- `sanitize` refuses a file that still has it waiting on a worker 60 s after the call as `too_slow`, a new refusal code, with the limit in seconds as its `limit`. It used to wait for as long as a file kept a worker busy, and on a file qpdf or pdf.js never finished it stayed pending, with the worker running and, for pdf.js, a frame left in the host page's body. The worker is now ended at the deadline and the frame taken out. Work on the calling thread is not interrupted or timed, so a call can settle later than 60 s, and one that has reached its last stage, the strip, returns its form. No form of the 59 is refused this way: the slowest takes 2.7 s.
- A background keeps of a link's border, of a destination and of a form's layers only what the strip's table lists. `/OCProperties` keeps its groups and its default configuration and no `/Configs`, a layer keeps its default state and loses the name of the application that wrote it (`/CreatorInfo`) and its usage by zoom, language and user, and a destination keeps its page only when the page tree holds it. An entry of `/Properties` that is no layer stays as an empty dictionary. Of the published forms measured, 7 backgrounds of 59 and 6 of 798 Air Force ones change, by `/CreatorInfo` alone, and no painted pixel does.
- A file in which two keys read one object as two kinds is refused as `damaged`, where the second key used to be deleted: a page's content stream that `/XObject` names as a form, or an array that both the default configuration's `/OFF` and a graphics state's `/TR` name, which left a layer the file turns off switched on in the background. None of 886 published files that reach the strip is refused for it, and every background of the forms that convert is the same bytes as before.
- A background keeps the published form's structure tree under the strip's table, where it kept it whole: the root, an element, a marked-content reference, an object reference, an attribute dictionary, the parent tree, the `/IDTree` and the mark information keep a listed set of keys each. An object reference to a widget, which the strip deletes, leaves the tree with it, so a `form.pdf` no longer holds a reference to an object it lacks, and an element that only the parent tree named is deleted. `/Namespaces` and `/NS` go. The tags keep their strings, alternate text and titles among them, which no page shows. Of the published forms measured, 6 backgrounds of the ten fixtures and 30 of 49 change, no painted pixel differs, and pdf.js reads the same tags from each fixture but for the leaves that named a widget. A file whose tags name one of its pages or kept links as an element is refused as `damaged`.

## 0.1.0

11 October 2026. The importer of `tonguetoquill/web-app-afa-demo@842ef4207cb5` as a library, on `@quillmark/wasm` 0.124.0.

- `sanitize(pdf)` reads a PDF form into a `Form`: a background with no form layer, the page sizes and one `Field` for each field a person can fill. A file it does not take comes back as a `Refusal`, a code with its data.
- Checkboxes that share a field name and turn on as different values come back from `sanitize` as one `radio` field for each box, with the shared name as `group` and the box's value as `on`. The first keeps the name as its `id` and the next is `name#2`. Checkboxes of one name that all turn on as one value stay one `checkbox` at several places.
- `suggest(fields)` names each field from its tooltip or its field name, and `check(fields, naming)` lists the problems of a naming. A naming of the wrong shape, a name that is no string for one, ends `check` and `quillify` with a `TypeError` that names the slot.
- `quillify(form, naming)` returns a quill's files, `Quill.yaml`, `form.json`, `form.pdf` and, when a kept field has an example to show, `example.md`, once `Quill.fromTree` has taken them, or the problems that stopped it.
- `@quillmark/wasm` is a peer dependency, at 0.124.0 or later.
- Each pdf.js read runs on a worker of its own, started from the worker the package ships. pdf.js's global worker settings are neither read nor written.
- The package carries its pdf.js worker (6.3.289 with a null guard at two sites), `qpdf.wasm` and its stage stylesheet in `assets/`, and loads them from there.
- A dynamic form is laid out in a sandboxed frame with a document of its own. No rule of the host page applies inside it, and the form's rules and fonts do not reach the host. The frame is hidden and has no size. It is in the host page's body while `sanitize` converts a file, dynamic or not, and is removed when that stage ends.
- The package has one entry point, built to `dist/`. `npm run build && npm pack` makes a tarball of the build, the three assets, `NOTICE` and pdf.js's license text.
